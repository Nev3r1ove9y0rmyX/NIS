# iKuai 三域网络搭建与配置步骤

负责人：D；关联 Issue：#16。
地址与策略依据：[docs/network-design.md](../../docs/network-design.md)（下称"设计文档"）。

本文记录可由另一名成员复现的完整配置步骤。**所有命令在课程授权的实验环境执行**，
不涉及任何第三方或公共网络目标。

## 0. 前置条件与设备清单

| 设备 | 角色 | 说明 |
|---|---|---|
| D 的电脑（≥16GB 内存） | 基础设施主机 | 运行虚拟化软件 + iKuai VM + srv-dmz-01 VM |
| 5/8 口千兆交换机 | 内网接入 | 连接四台终端与 iKuai LAN |
| 四台成员电脑 | 四角色终端 | 静态地址见设计文档 §4 |
| 外部测试机 | 外网验证 | 接现场上游或独立热点 |
| 网线若干 | - | 贴标签：WAN / LAN / DMZ |

## 1. iKuai 虚拟机创建

1. 在虚拟化软件（VMware/PVE/VirtualBox 均可）新建 VM：
   - 2 vCPU / 2GB 内存 / 8GB 磁盘；
   - **三块网卡**，按下表绑定；桥接目标为物理网卡名，现场记录到 §6 核对表；
2. 下载 iKuai 免费版 ISO（记录版本号，例如 `iKuai 3.x`）；
3. 从 ISO 引导安装到磁盘，安装完成后控制台显示 LAN 地址；
4. 首次登录：控制台或管理界面默认账号 `admin`，**首次登录立即改密**
   （口令保存于团队密码管理位置，不入仓库）。

| 虚拟网卡 | 虚拟化网络 | 桥接/仅主机 | 设计文档接口 |
|---|---|---|---|
| 网卡1 | 现场外网 VLAN/桥接 | 桥接至物理外网口 | `wan1` |
| 网卡2 | 内网交换机桥接 | 桥接至接交换机的物理口 | `lan1` |
| 网卡3 | DMZ 仅主机网络 | Host-Only（如 `vmnet-dmz`） | `dmz1` |

## 2. 接口配置

登录 `https://10.0.1.1`（首次从控制台确认地址）：

1. **网络设置 → 内外网分流 → 外网口（wan1）**：接入方式 DHCP（现场若允许可改静态）。
2. **网络设置 → 内外网分流 → 内网口（lan1）**：
   - IP：`10.0.1.1`，掩码 `255.255.255.0`；
   - DHCP 服务：开启，地址池 `10.0.1.200 - 10.0.1.249`，网关/DNS 指向自身；
   - 勾选"作为 DNS 服务器"（iKuai DNS 转发）。
3. **网络设置 → 内网扩展网络 → 新增 vlan/子接口**（将网卡3 配为独立网段）：
   - 名称 `dmz1`，绑定网卡3，IP `10.1.1.1`，掩码 `255.255.255.0`，**关闭 DHCP**。

> 不同 iKuai 版本菜单略有差异：目标是"三块网卡 = 三个不同网段，lan1 提供 DHCP/DNS"。
> 如版本支持直接把第三块网卡配为独立网口，等价可行，在 §6 记录实际菜单路径。

## 3. DMZ 服务主机接入

1. 创建 srv-dmz-01 VM（Ubuntu 22.04/24.04，建议 4 vCPU / 8GB），网卡接入与
   `dmz1` 相同的仅主机网络；
2. 静态网络配置（netplan 示例，路径 `/etc/netplan/01-dmz.yaml`）：

   ```yaml
   network:
     version: 2
     ethernets:
       ens192:            # 网卡名以 ip link 实际输出为准
         addresses: [10.1.1.20/24]
         routes:
           - to: default
             via: 10.1.1.1
         nameservers:
           addresses: [10.1.1.1]
   ```

3. `sudo netplan apply` 后验证：`ping 10.1.1.1` 通；`ping 10.0.1.1` **不通**
   （若通说明策略未生效，检查 §4 规则）；
4. 在 srv-dmz-01 安装 Docker 与 Compose 插件，部署步骤见
   [deploy/README.md](../README.md)。

## 4. 防火墙 ACL 规则录入

**网络设置 → 防火墙 → ACL 规则**，按下表**自上而下**逐条录入（顺序即匹配顺序，
先具体后兜底）。全部规则启用"记录日志"列注明的项。

| 序 | 启用 | 源地址 | 目的地址 | 协议 | 端口 | 动作 | 备注 |
|---|---|---|---|---|---|---|---|
| 1 | ✅ | 10.0.1.0/24 | any | any | - | 放行 | FW-01 内网上行 |
| 2 | ✅ | 10.0.1.0/24 | 10.1.1.20 | TCP | 80,443 | 放行 | FW-02 业务入口，开日志 |
| 3 | ✅ | 10.0.1.104/32 | 10.1.1.20 | TCP | 22 | 放行 | FW-03 管理终端 SSH，开日志 |
| 4 | ✅ | 10.0.1.0/24 | 10.1.1.0/24 | any | - | 拒绝 | FW-04 内网→DMZ 兜底，开日志 |
| 5 | ✅ | 10.1.1.0/24 | 10.0.1.0/24 | any | - | 拒绝 | **FW-05 核心**，开日志 |
| 6 | ✅ | 10.1.1.20/32 | 10.1.1.1 | UDP+TCP | 53 | 放行 | FW-06 DMZ DNS |
| 7 | ✅ | 10.1.1.20/32 | any | UDP / TCP | 123 / 443 | 放行 | FW-07 NTP/更新 |
| 8 | ✅ | 10.1.1.0/24 | any | any | - | 拒绝 | FW-08 DMZ 上行兜底，开日志 |
| 9 | ✅ | 10.0.1.104/32 | 10.0.1.1 | TCP | 443 | 放行 | FW-09 管理界面限源，开日志 |
| 10 | ✅ | any（wan1） | any | any | - | 拒绝 | FW-91 外部兜底，开日志 |

注意：

- iKuai 对 WAN 入站的默认行为依版本而异，**FW-91 兜底拒绝必须存在**；
- 端口映射（§5）优先生效于 ACL 的放行，因此外部可达范围 = 端口映射表 ∩ FW-91；
- 规则录入后立即按 [tests/network/](../../tests/network/README.md) 执行 TC-B04/TC-B07
  冒烟验证，再进行后续配置。

## 5. 端口映射（仅验收时段开启）

**网络设置 → 端口映射**：

| 名称 | 协议 | 外部端口 | 内部目标 | 启用 |
|---|---|---|---|---|
| MAP-01 | TCP | 80 | 10.1.1.20:80 | 验收时 ✅，平时 ❌ |
| MAP-02 | TCP | 443 | 10.1.1.20:443 | 有证书时 ✅ |

- 映射目标只允许 10.1.1.20 的 80/443；**禁止**将 3306、8000-8007、22 加映射；
- 每次开启/关闭记录时间与操作人（进 evidence），验收后立即关闭 MAP-01/02。

## 6. 配置核对与导出

配置完成后逐项核对并打勾（存档进 `evidence/TC-B03/`）：

- [ ] wan1 获得上游地址（记录：____）
- [ ] lan1 = 10.0.1.1/24，DHCP 池 10.0.1.200-249
- [ ] dmz1 = 10.1.1.1/24，无 DHCP
- [ ] 四台终端静态地址与设计文档 §4 一致，网关/DNS = 10.0.1.1
- [ ] srv-dmz-01 = 10.1.1.20/24，网关/DNS = 10.1.1.1
- [ ] ACL 10 条规则与 §4 一致，顺序正确
- [ ] 端口映射仅 MAP-01/02 且处于关闭状态
- [ ] iKuai 管理账号已改默认口令；管理界面仅 lan1 可达

最后：**系统设置 → 配置备份 → 导出配置**，文件存 D 本地 `configs/ikuai/ikuai-YYYYMMDD.dat`
（不入仓库）。变更配置后重新导出。

## 7. 恢复

| 故障 | 恢复步骤 |
|---|---|
| iKuai 配置丢失 | 配置导入最近导出文件，或恢复 VM 快照 |
| srv-dmz-01 不可达 | 从 term-d `ping 10.1.1.1` 分段定位：通则查主机，不通查 iKuai |
| 误开危险映射 | 立即关闭端口映射条目 → 验证 TC-B05 负向 → 记录事件 |
| 误改 ACL 被锁 | 虚拟机控制台登录 iKuai，恢复默认或导入配置备份 |
