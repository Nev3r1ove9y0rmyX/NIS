## 一、AI 不可用（降级）

`AI_ENABLED=false` 时请求建议：

```text
POST /api/v1/ai/suggestions  ->  503
{"code":"SERVICE_UNAVAILABLE","message":"AI 建议服务当前不可用，请人工完成该环节","request_id":"6c538b71-…"}
```

符合 NFR-AI-001：AI 不可用时**不阻断人工流程**，且错误信息明确提示人工完成。
（同一环境下侦察、分析、决策、执行四段业务此前已全部跑通。）

## 二、AI 可用（正向）

`AI_ENABLED=true` 时：

1. 请求建议 → `200`，`status = pending`，`model_name = nis-rule-based`，`confidence = 0.6`，
   内容为结构化摘要（headline / items / caveat 三部分）；
2. 人工接受 → `status = accepted`，`human_confirmed_by = 093aeb2a…`（recon01），
   `human_confirmed_at = 2026-10-28T04:46:30Z`；
3. 重复处理同一建议 → **409**，不会重复确认；
4. 非法参数校验：`decision = edited` 但缺少 `edited_content` → **400 INVALID_REQUEST**
   （“选择修改时必须提供修改后的内容”），说明“修改”分支要求人工提供最终内容。

## 落库

```text
ai.db  ai_requests = 1    ai_suggestions = 1
       ai_suggestions.status = accepted, confidence = 0.6
```

## 结论

- AI 输出只作为建议，必须经人工确认后才改变 `ai_suggestions.status`；
- 建议本身不驱动任何业务状态（业务提交仍走各自接口）；
- 降级与正向两条路径均可复现，符合 `docs/workflow.md` 第 7 节“AI 人在回路”。
