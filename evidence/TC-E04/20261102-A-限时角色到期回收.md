# 扩展目标 E4 限时角色到期自动回收（2026-11-02）

- 测试人：A
- 环境：本机 SQLite 全栈，`develop @ c56bd00`
- 方式：接口级演示（无需前端）
- 账号：`admin`（`administrator` 角色上下文）、`exec02`（原为单角色执行员）

## 步骤与结果

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | `POST /admin/users/{exec02}/roles`，`role_code=analyst`，`expires_at=2026-11-02T12:33:34Z`（约 60 秒后） | HTTP 201，绑定成功 |
| 2 | 重新登录，返回角色 `['analyst','executor']` | 多角色生效 |
| 3 | 有效期内 `GET /analysis-reports` | HTTP 200 |
| 4 | 等待 70 秒后重新登录 | 角色列表回到 `['executor']` |
| 5 | 到期后同名接口 | **HTTP 403 FORBIDDEN** |

## 结论

- 角色绑定支持 `expires_at`，到期后**自动从有效角色中消失**，无需人工撤销；
- 回收由权限解析时的过滤实现（`user_roles.expires_at > now`），因此对**下一次请求立即生效**，
  不依赖定时任务或后台清理作业；
- 到期后相关权限同步失效（分析接口返回 403）。

## 与验收口径的差异

验收模板要求“后台为普通用户分配临时角色并设置生效/过期时间”。当前通过接口完成配置，
效果与页面配置一致，但缺页面入口；现场可用 Postman/Swagger 演示，并在报告已知限制中说明。

页面入口见 Issue #45（与细粒度权限同一页面）。
