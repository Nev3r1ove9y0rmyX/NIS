# TC-B01 中心数据库与数据存储（2026-10-28）

- 测试人：A
- 环境：本机 SQLite 全栈（`develop @ 6408da0`），7 个服务各一个数据库文件，等效“中心数据库按 Schema 划分”
- 方法：用四类角色通过公共接口完成一轮业务，随后直接查库核对

## 核对结果

```text
iam.db        organization_units=5  users=8  roles=5  permissions=18
              role_permissions=24  user_roles=9
recon.db      recon_records=1  recon_assignments=1  recon_evidence=0
analysis.db   analysis_reports=1  report_recon_links=1  report_assignments=1
decision.db   commands=1  command_assignments=1  command_conflict_checks=1
execution.db  execution_assignments=1  execution_evidence=0
audit.db      audit_events=22  audit_trace_index=17
```

## 结论

1. **关键业务数据全部落库**：侦察记录、分析报告、指令、执行结果各 1 条，与界面/接口提交字段一致；
2. **一次业务只产生一条记录**：重复执行种子脚本时四类对象不会重复创建（脚本按标题/用户名判重）；
3. **附件类**：本次未上传证据文件，`recon_evidence` 与 `execution_evidence` 为 0，属预期；
4. **无跨 Schema 写入**：每个服务只写自己的库文件（对应正式环境的 Schema 账号隔离）。

## 限制

本次为 SQLite；MySQL 8 的建库、账号与授权（D-06）由 D 在 `deploy/` 环境复验，见 Issue #17。
