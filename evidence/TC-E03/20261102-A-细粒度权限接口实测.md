# 扩展目标 E3 细粒度功能权限拆分（2026-11-02）

- 测试人：A
- 环境：本机 SQLite 全栈，`develop @ c56bd00`
- 方式：**接口级演示**（前端暂无权限管理页，故不依赖界面；权限判定在后端，效果等价）
- 账号：`admin`（角色上下文 `administrator`）、`analyst01`

## 断言与结果（9 条全部通过）

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | `GET /admin/roles` 读取 `analyst` 角色权限 | 共 6 项，包含 `analysis:read_assigned` |
| 2 | 关闭前 `analyst01` 调 `GET /analysis-reports` | HTTP 200 |
| 3 | 管理员 `PUT /admin/roles/{id}/permissions` 去掉 `analysis:read_assigned` | HTTP 200，剩余 5 项 |
| 4 | 关闭后 `analyst01` 再调同一接口 | **HTTP 403 FORBIDDEN** |
| 5 | 恢复原权限后再次调用 | HTTP 200（立即生效） |
| 6 | 到期角色相关断言（见 E4） | 4 条通过 |

## 结论

- 同一角色可**单独开关某项权限**（本例为“查看分析报告”），不需要改代码；
- 权限变更**即时生效**，不需要用户重新登录（后端每请求向 IAM 取权限）；
- 关闭后请求返回 403，符合 `docs/rbac.md` 的授权顺序。

## 与验收口径的差异

验收模板要求“进入后台权限管理界面”配置。当前通过 **REST 接口**完成同样的配置，
后端行为一致，但缺页面。现场演示时建议：

1. 用 Postman/Swagger 调 `PUT /admin/roles/{id}/permissions`，同时展示两次受控请求的 200/403；
2. 如实说明“管理界面未做，接口已实现”，并把它列在报告的已知限制里。

**2026-11-03 更新**：管理页面已实现（审计工作台 → 系统管理 → 角色权限），可在浏览器内勾选/取消权限并保存，效果与本文接口调用一致。
