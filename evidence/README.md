# evidence

验收证据目录，A 统一管理，各成员按用例提交。

## 命名规则

```text
evidence/<用例编号>/<YYYYMMDD>-<角色或成员>-<内容>.<扩展名>
```

示例：

```text
evidence/TC-B03/20261016-D-三域网段配置.png
evidence/TC-B09/20261016-C-侦察员访问决策接口403.png
evidence/TC-B12/20261016-A-完整OODA链数据库核对.txt
evidence/TC-D02/20261016-A-种子脚本执行输出.txt
```

## 每个用例至少需要

| 内容 | 说明 |
|---|---|
| 操作步骤 | 一条命令或几步点击，别人能照做 |
| 预期结果 | 与追踪矩阵的验收条件一致 |
| 实际结果 | 截图、命令输出或日志片段 |
| 环境 | 构建提交号、访问地址、测试账号（只写用户名，不写密码） |

## 脱敏要求

- 截图与日志中不得出现真实密码、Token、私钥、Cookie；
- 不得出现与课程无关的第三方目标信息；
- 外部 IP、主机名如涉密需改为示例值并注明“已脱敏”；
- 课程原始 PDF/DOCX、抓包原件、虚拟机镜像一律不进入仓库。

## 体积控制

- 单张截图建议小于 500 KB，用 PNG；长日志只保留关键片段；
- 不提交数据库备份、`*.pcap`、`*.pcapng`（已在 `.gitignore` 中排除）；
- 录屏只放链接或本地文件，不直接入库。

## 与验收的对应

证据编号即 [需求追踪矩阵](../docs/traceability.md) 中的用例编号。中期验收前由 A 与 D
共同核对：每个 P0 用例都有证据，证据内容与报告中的描述一致。
