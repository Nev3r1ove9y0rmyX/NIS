# 扩展目标 E8 任务转交（2026-11-02）

- 测试人：A
- 环境：本机 SQLite 全栈，`develop @ 1d0bbd0` + 本轮本地实现（未提交）
- 实现：`POST /api/v1/assignments/{id}/transfer`。旧分配置为 `cancelled` 并记录转交说明，为目标执行员新建一条 `pending` 分配（沿用指令快照）；执行侧向决策侧回写两次（旧行终态、新行 pending），决策侧聚合状态按剩余活动分配重算。

## 断言（11 条全部通过）

| 断言 | 结果 |
|---|---|
| 执行员甲持有待办分配 | pending |
| 转交成功 | 200 |
| 新分配归属乙且为 pending | 通过 |
| 新分配内容完整（标题/正文快照一致） | 通过 |
| 旧分配变为 cancelled | 通过 |
| 甲待办中不再有待办（仅保留已取消记录） | 通过 |
| 乙待办中出现该任务 | 通过 |
| 决策侧聚合状态为 issued | 通过 |
| 乙完成后指令聚合状态为 completed | 通过 |
| 已完成任务不可转交 | 409 |
| 转交给已持有该指令的执行员 | **400 INVALID_REQUEST** |

## 关键实现点

- **两侧一致性**：决策侧摘要按 `(指令, 执行员)` 唯一，转交必须"旧行置终态 + 新行建 pending"两次回写；决策服务对首次出现的新分配做 upsert，否则摘要会漏掉接收人；
- **状态机**：仅 `pending / accepted / executing` 可转交，终态一律拒绝；
- **聚合规则**：`recompute_status` 计算时排除 `cancelled`，所以旧行取消不会让指令变成"部分完成"。
