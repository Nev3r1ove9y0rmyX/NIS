# tests

测试目录，A 负责追踪与验收组织，B/C/D 按职责编写。

## 分层

```text
tests/
  contract/    契约测试：字段名、错误码、状态码、幂等行为（B，P1）
  integration/ 接口测试：登录、权限、四类资源、非法状态转换（B，P1）
  e2e/         端到端：完整 OODA 闭环、多用户并发、重复提交（A 组织，全员配合）
  network/     网络测试：三域连通、拒绝、端口映射（D，P0）
```

## 命名与对应关系

用例编号沿用 [需求追踪矩阵](../docs/traceability.md)：`TC-B01` 至 `TC-B15`、
`TC-SOA01` 至 `TC-SOA05`、`TC-E01` 至 `TC-E03`、`TC-D01` 至 `TC-D02`。

每条用例的文件名格式：

```text
tests/<层>/test_<用例编号小写>_<简述>.py
tests/network/<用例编号小写>_<简述>.md      # 网络测试用命令记录 + 结果
```

## 必须覆盖的失败场景

| 场景 | 期望 |
|---|---|
| 无 Token / Token 过期 | 401，不泄露资源信息 |
| 角色越权（侦察员访问决策接口） | 403，并写安全审计 |
| 直接改 URL 访问他人资源 ID | 403 或 404（按防泄露规则），不得返回数据 |
| 旧 `expected_version` 提交 | 409 `VERSION_CONFLICT` |
| 非法状态转换（已完成后再次开始） | 409 `WORKFLOW_CONFLICT` |
| 相同幂等键重复提交 | 返回原结果，不创建第二条记录 |
| 下游服务超时 | 明确失败，不显示成功；状态可识别 |
| AI 服务不可用 | 建议功能降级，人工流程仍可提交 |

## 证据规则

- 自动化测试记录以 CI 日志或 `pytest` 输出为准；
- 现场演示与手工测试的截图放 `evidence/`，命名见
  [evidence/README.md](../evidence/README.md)；
- 失败记录同样保留，修复后追加复测结果，不覆盖历史。
