# NIS 前端用户操作说明

适用版本：2026-10-28（前端 0.2.0，对接 `contracts/openapi/api-gateway.yaml` 冻结基线 1.0）。
本版**所有页面都连接真实后端接口**，不再有演示用内存原型。

## 1. 谁用、看到什么

| 账号 | 角色 | 进入的工作台 | 能做什么 |
|---|---|---|---|
| `recon01` / `recon02` | 侦察员 | 侦察工作台 | 新建侦察记录、保存草稿、提交并指派分析员、查看本人记录 |
| `analyst01` / `analyst02` | 分析员 | 分析工作台 | 读取被指派的侦察记录、写分析报告、处理 AI 建议、提交给决策员 |
| `dmaker01` | 决策员 | 决策工作台 | 读被指派的报告、创建指令、冲突检查、下达、查看执行状态与结果 |
| `exec01` / `exec02` | 执行员 | 执行工作台 | 接收/拒绝指令、开始执行、提交结果与证据 |
| `admin` | 决策员 + 管理权限束 | 决策工作台 + 审计与调用链 | 审计查询、按请求 ID 还原调用链 |

- 一个账号可以有多角色：登录后左侧列出它拥有的工作台，切换工作台只改变上下文，不额外增加权限。
- 账号口令由部署者通过 `NIS_ADMIN_PASSWORD` / `NIS_DEMO_PASSWORD` 注入，不写在仓库里，也不要投屏。
- 权限由后端判定。页面上隐藏按钮只是为了少让人点错，**不是安全边界**。

## 2. 登录与退出

1. 打开前端地址（开发环境形如 `http://127.0.0.1:5173/login`，本机端口被占用时按终端提示的端口）。
2. 输入账号与口令，点「登录工作台 →」。
3. 登录成功后自动进入你角色对应的工作台；如果是被踢回登录页，地址栏 `?next=` 会带回原来的页面。
4. 退出：右上角「退出」。服务端写一条 `auth.logout` 审计，客户端立即丢弃 Token。

失败提示的含义：

| 提示 | 含义 | 怎么办 |
|---|---|---|
| 用户名或密码不正确 | 账号或口令错误（401） | 核对后重试；连续失败多次会被临时锁定（423） |
| 账号已被临时锁定 | 登录失败次数过多 | 等锁定期结束或联系管理员 |
| 当前账号没有可用的业务角色 | 账号没分配角色 | 让管理员在 IAM 里分配角色 |
| 无法连接服务，请确认 Gateway 已启动 | 后端没起或地址不对 | 先确认后端 `/health/ready` 返回 200 |

## 3. 侦察员：采集与提交

1. 侦察工作台列出**你自己**创建的记录，可按状态筛选、按编号/标题/来源搜索，分页每页 10 条。
2. 点「＋新建侦察记录」，填写标题（2–200 字）、来源类型、可信度、优先级、来源说明、正文（10–8000 字）。
3. 证据：可添加 PNG/JPEG/PDF/TXT，单个 ≤10 MB、最多 5 份。浏览器会算出 sha256 随记录一起提交。
   **注意**：当前接口契约没有上传端点，服务端只收到元数据，所以下载时可能提示「证据文件不在服务端受控目录」。
4. 「保存草稿」→ 记录进入 `草稿`，你可以继续改。草稿一旦提交就不能再直接改写。
5. 「提交给分析员 →」会先做一次表单校验，再弹出确认区：在这里**勾选分析员**（名单来自服务端候选接口：账号启用 + 角色有效 + 组织范围），确认后状态变为 `已指派待分析`。
6. AI 建议（可选）：草稿保存后出现「请求 AI 建议」，返回的是规则模板摘要，需要你点「接受建议 / 修改建议 / 舍弃」之一；
   未经处理的建议不会进入正文，也不会影响提交。
7. 详情里能看正文、来源、指派情况、证据列表与下载按钮。

## 4. 分析员：研判与提交

1. 分析工作台有两个标签：「待分析侦察记录」（服务端指派给你的）与「我的分析报告」。
2. 在待分析记录行点「写报告 ↗」，会带着这条记录打开报告面板；也可点右上角「＋编写分析报告」自己选记录（可多选）。
3. 填写标题、关键发现（10–8000 字）、关联关系、建议手段、风险等级、优先级。
4. AI 建议：可「请求 AI 建议 → 修改建议 → 修改后采用」，或直接接受/舍弃。
5. 「保存草稿」后可继续修改；「提交给决策员 →」要求：至少一名决策员 + **勾选「我已逐条处理 AI 建议」**（后端 fail-closed，不确认直接 422/400）。
6. 提交后状态变为 `已提交待研判`，作者不能再改；要改只能走退回+新版本流程（A 的状态机规定）。

## 5. 决策员：下达与跟踪

1. 决策工作台列出指派给你的报告与你的指令，可切换标签、按状态筛选。
2. 在报告行点「下达指令 ↗」，填标题、目标、行动内容、优先级、截止时间（可空）。
3. 「保存草稿」后点「冲突检查并下达 →」：
   - 系统按同一依据报告/同一目标查活动指令；
   - 没有冲突 → 直接显示「没有发现冲突」；
   - 有冲突 → 列出已存在的指令编号与原因，必须勾选「知悉冲突并继续」才能下达（会写高重要度审计）。
4. 在确认区勾选一名或多名执行员（候选同样来自服务端筛选），点「确认下达」。
5. 下达后面板转为只读：可看总体状态、每名执行员的分配状态、执行结果。
   需要变更时用「取消指令」（必须填理由），再新建一条 —— 已下达的指令不能被改写。

## 6. 执行员：接收与反馈

1. 执行工作台只显示分配给你的任务，可按状态筛选。
2. 点任务行按钮打开面板：先「接收指令」，再「开始执行」，最后「填写结果并提交」。
3. 结果表单：结论（成功/部分完成/失败）、结果摘要（必填）、过程与异常、证据。
4. 也可以「拒绝」，必须填理由（至少 2 字），决策员能看到理由。
5. 已提交的结果不能重复提交（重复请求返回原结果或 409）。

## 7. 审计与调用链（管理权限束）

1. `admin` 登录后左侧出现「审计与调用链」。
2. 列表可看时间、服务、动作、操作者、结果、请求 ID；点表格最后一列的请求 ID 会自动填入查询框。
3. 点「还原调用链」后，上方显示该次请求跨服务的全部事件（例如 `execution-service: execution_assignment.complete` 与 `decision-service: command.status.recalculated` 同属一个请求）。
4. 审计表只追加，前端不提供任何修改或删除入口。

## 8. 列表与提示的一致行为

每个列表页都区分四种状态：

| 状态 | 界面表现 |
|---|---|
| 加载中 | 转圈 + 「正在加载…」，按钮禁用，避免重复提交 |
| 空数据 | 说明为什么为空，并给出下一步动作（例如「新建侦察记录」） |
| 无权限 | 「没有查看权限」+ 说明，不暴露资源是否存在 |
| 失败 | 显示原因 + 请求 ID（报障时用），可重试；网络错误与超时区分开 |

提交类操作在成功后给出绿色提示，失败给出红色提示；冲突类提示会停留更久，方便读完原因。

## 9. 常见错误对照

| 现象 | 后端原因 | 处理 |
|---|---|---|
| 「这条记录已被其他成员更新」 | 409 `VERSION_CONFLICT`（别人先改了） | 刷新后重新核对再提交，别直接覆盖 |
| 「当前状态不允许这个操作」 | 409 `WORKFLOW_CONFLICT`（例如已提交还想改草稿） | 刷新看最新状态 |
| 「必须先逐条确认或舍弃 AI 建议内容」 | 提交报告时没确认 AI 内容 | 回到 AI 面板处理建议，再勾选确认 |
| 「只有记录创建者可以执行该操作」 | 403（越权） | 只操作自己的记录；需要协作时让创建者改 |
| 「侦察记录不存在」 | 404（无权限或真的不存在） | 确认是否被指派给你 |
| 「请至少选择一名分析员/决策员/执行员」 | 提交缺指派 | 在确认区勾选人员 |
| 「证据文件不在服务端受控目录」 | 下载 404（元数据在库里，文件没上传） | 属当前契约限制，见联调清单第 4 节 |

## 10. 演示建议（10 分钟）

| 时间 | 操作 | 讲解要点 |
|---|---|---|
| 0:00–1:00 | 四个账号各登录一次 | 角色不同 → 工作台不同；侦察员访问决策台被拦到 403 页面 |
| 1:00–3:00 | 侦察员建记录 → 存草稿 → AI 建议 → 接受 → 提交并勾选分析员 | AI 只是建议，人确认后才生效 |
| 3:00–5:00 | 分析员写报告 → AI 修改后采用 → 提交（勾选确认） | 报告只引用指派给自己的记录 |
| 5:00–7:00 | 决策员冲突检查 → 勾选执行员 → 二次确认下达 | 有冲突必须显式确认，写审计 |
| 7:00–8:30 | 执行员接收 → 开始 → 提交结果 | 每步都有版本校验，重复提交不会产生第二份 |
| 8:30–10:00 | 决策员看结果 → 审计页按请求 ID 还原调用链 | 一条请求能串起两个服务的事件 |
