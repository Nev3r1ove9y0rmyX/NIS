# Sprint 01：设计基线与首个可运行切片

周期：由团队填写开始和结束日期（建议 5 至 7 天）

Sprint 目标：完成设计评审，并得到“登录 -> 侦察员提交记录 -> 分析员查询记录”的真实可运行版本。

## 任务 A：评审并冻结设计基线

负责人：A

依赖：无

优先级：P0

工作范围：

- 组织全员评审 `course-requirements-checklist.md`、`requirements.md`、`rbac.md`、`workflow.md`、`architecture.md`。
- 收集逐条意见并修订；需要改变范围的意见建立决策记录。
- 与 B 确认实体、状态、权限代码和错误码；与 C 确认页面动作；与 D 确认 DMZ 数据库方案。
- 更新追踪矩阵和本 Sprint 风险。

验收标准：

- [ ] 四人均完成评审，文档中没有已知互相矛盾的 P0 规则。
- [ ] B 能据此提交 ER 图/OpenAPI，C 能据此制作页面，D 能据此搭建网络。
- [ ] 关键决策和未决问题有明确责任人及截止时间。

## 任务 B：后端骨架、IAM 数据模型与侦察 API

负责人：B

依赖：A 设计基线评审

优先级：P0

工作范围：

- 初始化 FastAPI、SQLAlchemy、Alembic、MySQL 和 pytest。
- 设计 User、Role、Permission、UserRole、RolePermission、OrganizationUnit 基础模型。
- 实现用户名密码登录、当前用户、角色与权限响应。
- 实现侦察记录草稿、提交和分析员授权列表的最小 API。
- 提交 ER 图和 OpenAPI，状态及权限代码与基线一致。

验收标准：

- [ ] 新环境可以迁移数据库并创建四类演示账号。
- [ ] 合法账号登录成功，错误密码失败，密码不明文保存。
- [ ] 侦察员可提交记录；未授权用户不能调用提交接口。
- [ ] 被指派分析员可查询记录，其他分析员无权读取。
- [ ] 自动化测试覆盖正常、未认证、越权和非法参数。

## 任务 C：前端骨架、登录和侦察工作台

负责人：C

依赖：B 提供 OpenAPI 或稳定 mock 契约

优先级：P0

工作范围：

- 初始化 Vue 3、Vite、TypeScript、路由和 API 客户端。
- 实现登录、当前用户/角色展示和权限路由。
- 实现侦察记录列表、新建、草稿和提交页面。
- 实现分析员的被指派记录只读列表，作为第一切片终点。
- API 未就绪时 mock 必须与 OpenAPI 一致且可一键切换，最终验收连接真实 API。

验收标准：

- [ ] 四类账号登录后角色展示正确，无权限路由被拦截。
- [ ] 侦察员能通过真实 API 提交记录且失败时输入不丢失。
- [ ] 分析员能查询被指派记录。
- [ ] 加载、空数据、401、403、422 和 500 有明确界面。
- [ ] lint、typecheck、test、build 通过。

## 任务 D：环境盘点与三域网络最小环境

负责人：D

依赖：A 架构基线

优先级：P0

工作范围：

- 盘点四台电脑、内存、网卡、虚拟化软件、交换机/路由器和现场限制。
- 固化外网、内网、DMZ 的地址、网关、虚拟网卡和节点清单。
- 创建 iKuai/等价软路由及三个网段。
- 在 DMZ 预留 Web/API 和数据库地址，数据库不映射外网。
- 完成三域基础连通/拒绝测试，记录尚未部署应用时的测试边界。

验收标准：

- [ ] 三个区域是不同网段，地址表和拓扑与实际环境一致。
- [ ] 内网能访问外网和 DMZ 测试服务。
- [ ] 外网能访问映射后的 DMZ 测试服务。
- [ ] DMZ 不能访问内网测试服务，防火墙日志可证明拒绝。
- [ ] 配置步骤可由另一名成员复查。

## Sprint 联合验收

1. D 提供可访问的 DMZ 部署环境或可复现的本地替代环境。
2. B 部署 API 和数据库，执行迁移和种子数据。
3. C 部署前端并连接真实 API。
4. A 使用侦察员账号提交一条固定演示记录。
5. A/B 使用分析员账号查询该记录。
6. 四人核对数据库数据、访问控制和审计日志。
7. 把构建提交号、测试结果和脱敏证据记录到追踪矩阵。
