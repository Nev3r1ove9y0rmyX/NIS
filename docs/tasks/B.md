# 成员 B 任务书：后端、数据库、权限与审计

## 角色定位

你负责系统的数据可信性和服务端规则，演练时担任分析员。前端隐藏按钮不等于权限控制，所有权限和状态转换必须由后端再次验证。

## 必须完成的任务

### B-01 初始化后端工程

- 创建 FastAPI 工程结构，区分 API、业务服务、数据模型、Schema、配置和测试。
- 配置 SQLAlchemy、数据库迁移、统一异常处理、结构化日志和健康检查。
- 提供 `.env.example`，所有密钥和数据库密码从环境变量读取。
- 提供本地启动、测试和迁移命令。

验收：新环境按照 README 能启动；`/health` 能区分应用存活和数据库连接状态。

### B-02 设计中心数据库

至少实现以下实体：

- 用户和角色；
- 侦察记录及其证据；
- 分析报告和关联关系；
- 决策指令和接收人；
- 执行结果和附件；
- 审计日志；
- 必要的版本号、创建人、更新人、时间和状态字段。

要求：外键和唯一约束合理；时间统一保存；枚举值集中定义；重要业务记录避免物理删除。

### B-03 实现认证和 RBAC

- 密码使用成熟密码哈希算法存储，不得明文或可逆加密。
- 实现登录、当前用户、Token 校验和失效处理。
- 后端按角色和资源所有权执行权限判断。
- 对失败登录、越权和无效 Token 留下安全日志。

验收：分别使用四类账号调用全部关键接口，允许和拒绝结果符合权限矩阵。

### B-04 实现侦察记录 API

- 创建、保存草稿、修改、提交、列表、详情。
- 已提交记录按业务规则禁止任意修改。
- 支持来源、摘要、正文、可信度、标签和证据元数据。
- 所有查询进行分页、排序和参数校验。

### B-05 实现分析报告 API

- 分析员读取被授权的侦察记录。
- 创建分析报告，关联一条或多条侦察记录。
- 保存关键信息、关联关系、优先级、建议手段和人工确认状态。
- 支持提交、退回和版本冲突检测。

AI 输出只能进入“建议/草稿”，不得自动批准或直接生成行动指令。

### B-06 实现决策指令 API

- 决策员读取分析报告并创建指令。
- 指令包含目标、内容、优先级、接收执行员、截止时间和依据。
- 实现下达、撤回、拒绝和状态查询。
- 阻止重复下达、非法接收人和越级修改。

### B-07 实现执行结果 API

- 执行员只能查看分配给自己或所属范围的指令。
- 实现接收、开始执行、提交结果、报告失败和补充证据。
- 后端校验状态转换，避免重复执行或完成后篡改。

### B-08 实现不可遗漏的审计日志

日志至少记录：操作者 ID、角色、动作、资源类型、资源 ID、发生时间、来源 IP、请求追踪 ID、成功或失败、失败原因。

要求：

- 登录、查询敏感详情、创建、修改、提交、审批、下令和反馈全部记录；
- 日志查询接口仅授权角色可用；
- 不把密码、Token、完整敏感正文写入日志；
- 审计写入失败时有明确处理策略。

### B-09 提供 API 文档和测试

- OpenAPI 文档包含请求、响应、错误码和示例。
- 单元/集成测试覆盖权限、状态转换、非法参数、重复提交和并发更新。
- 准备可重复执行的种子数据脚本。

最低验收：核心 API 自动化测试通过；无法通过直接构造 HTTP 请求绕过前端权限。

### B-10 支持部署与恢复

- 配合 D 编写 Dockerfile、Compose 配置和健康检查。
- 提供数据库初始化、迁移、备份和恢复说明。
- 验证数据库仅被允许的应用主机访问。

## 接口质量约束

- API 使用 `/api/v1` 版本前缀；
- HTTP 状态码语义正确；
- 错误返回包含稳定错误码和可读信息；
- 不把堆栈、SQL、密钥或内部路径暴露给客户端；
- 列表接口默认分页；
- 更新操作考虑并发冲突；
- 输入长度、类型和允许值在服务端验证。

## 完成定义

B 的工作完成意味着：数据库可迁移、API 文档可用、权限不可被客户端绕过、业务状态一致、审计链完整、自动化测试能复现结果并能配合 D 完成部署。
