# 成员 D 任务书：网络、部署、安全与测试

## 角色定位

你负责让系统在真实的分区网络中稳定运行，并用可重复的测试证明确实满足访问控制要求，演练时担任执行员。不要只提交一张拓扑图，必须完成配置和验证。

## 必须完成的任务

开始前先阅读 [四台电脑的组网与部署建议](../network-lab-plan.md)。日常开发不要求四台电脑位于同一网络；集成和验收时应让四台终端进入同一受控局域网。条件允许时使用独立交换机进行有线连接，DMZ 使用独立虚拟网段实现。

### D-01 设计网络拓扑

拓扑至少包含：

- 外部网络；
- DMZ；
- 信任内网；
- 虚拟软路由或防火墙；
- 应用服务；
- 中心数据库；
- 四类操作终端或可替代的测试终端。

在 `docs/network-design.md` 中记录每个节点的名称、区域、用途、IP、掩码、网关、DNS、开放端口和管理方式。

### D-02 建立虚拟环境

- 创建外部、DMZ、内网虚拟网络；
- 为路由/防火墙配置 WAN、LAN、DMZ 接口；
- 创建应用、数据库和测试虚拟机或等价容器环境；
- 使用固定、可重复的命名和地址规划；
- 保存配置步骤，不提交虚拟机镜像到 Git。

### D-03 配置路由、防火墙和端口映射

最低策略：

- 内网到业务所需的 DMZ 服务按需允许；
- DMZ 到内网默认拒绝，只为明确依赖开放最小端口；
- 外部到 DMZ 只开放演示所需端口；
- 外部不得直接访问数据库；
- 路由器、数据库和服务器管理端口不得不必要地暴露；
- 记录每条规则的源、目的、协议、端口、动作和理由。

不要笼统使用“全部放行”作为最终方案。

### D-04 部署系统

- 与 B 编写后端和数据库容器配置；
- 与 C 确认前端构建及 API 地址；
- 设置服务启动顺序、健康检查、日志目录和重启策略；
- 提供从空白环境部署、更新、回滚的操作说明；
- 使用环境变量和非默认凭据。

### D-05 建立备份和恢复能力

- 设计数据库备份命令和保存位置；
- 实际恢复到测试实例并核对关键记录；
- 说明配置文件和上传证据的备份范围；
- 记录恢复所需时间和已知限制。

### D-06 执行网络验证

至少覆盖：

1. 内网终端能够访问允许的系统服务；
2. 多终端可同时登录；
3. 外部网络可以访问公开服务；
4. 外部网络不能访问数据库和管理端口；
5. DMZ 主机不能主动访问被保护的内网服务；
6. 必要业务流量仍能通过；
7. 防火墙日志能证明允许和拒绝结果。

每个测试记录前置条件、命令、期望、实际结果、时间和截图/日志路径。

### D-07 执行安全基线检查

- 修改所有默认口令；
- 检查弱口令、共享口令和明文密钥；
- 检查未使用端口和服务；
- 检查数据库是否被外部访问；
- 检查最小权限、日志、系统更新和时间同步；
- 检查备份是否可恢复；
- 配合 B 验证越权和敏感错误信息问题。

仅在课程授权的本地实验环境进行安全测试，不触碰第三方系统或公共网络目标。

### D-08 编写系统与网络测试报告

在 `tests/` 和 `evidence/` 中保存经过脱敏的测试记录，在 `docs/test-report.md` 汇总：

- 测试环境；
- 功能、接口、网络和安全测试范围；
- 测试用例与结果；
- 缺陷和修复验证；
- 未解决风险；
- 中期验收结论。

### D-09 准备演练环境和恢复预案

- 演练前创建配置与数据库备份；
- 检查演示账号、网络地址、系统时间和日志；
- 准备服务重启、数据库恢复和网络配置恢复步骤；
- 预演执行员接收指令、提交结果的流程；
- 演练结束后保留必要证据并恢复环境。

## 网络完成定义

D 的工作完成意味着：网络拓扑已实际搭建，最小权限策略可由测试证据证明，系统可从文档重新部署，数据库可恢复，四人可以从不同终端使用系统，演练故障有明确恢复步骤。
