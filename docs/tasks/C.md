# 成员 C 任务书：前端、交互与四角色工作台

## 角色定位

你负责把业务流程变成清晰、稳定、可演示的操作界面，演练时担任侦察员。你的目标是让四类用户知道“现在有什么任务、能做什么、下一步是什么、操作是否成功”。

## 必须完成的任务

### C-01 初始化前端工程

- 使用 Vue 3、Vite 和 TypeScript。
- 建立路由、状态管理、API 客户端、页面、组件和类型目录。
- API 地址从环境变量读取。
- 统一请求拦截、Token 附加、错误处理和登录失效跳转。

验收：开发环境可启动；代码没有写死生产地址或真实账号。

### C-02 建立界面规范和原型

- 定义导航结构、表单、表格、状态标签、确认对话框和反馈消息规范。
- 完成登录页、四类工作台、详情页和审计查询页原型。
- 明确加载、空数据、错误、无权限和提交中的状态。
- 桌面端至少适配常见 1366×768 与 1920×1080 屏幕。

### C-03 实现登录和权限路由

- 登录成功后获取用户和角色信息。
- 不同角色进入对应工作台并只显示允许的菜单。
- 无权限路由显示明确页面，不能出现空白屏。
- Token 过期后清理本地状态并跳转登录。

注意：前端权限只改善体验，真正权限由后端控制；不得假设隐藏按钮就足够安全。

### C-04 实现侦察员工作台

- 待办或记录列表；
- 新建、编辑和保存草稿；
- 填写来源、摘要、正文、可信度和标签；
- 上传或关联证据；
- 提交前确认，提交后显示状态；
- 查看本人历史记录和处理进度。

验收：必填项、长度和类型校验明确；失败不会丢失尚未提交的输入。

### C-05 实现分析员工作台

- 显示待分析侦察数据；
- 支持查看详情和相关证据；
- 编辑关键信息、关联关系、优先级和建议手段；
- 清晰区分 AI 建议、人工修改和最终确认内容；
- 支持保存草稿、提交和查看退回原因。

### C-06 实现决策员工作台

- 查看分析报告及其依据；
- 创建行动指令；
- 选择一个或多个允许的执行员；
- 设置优先级、截止时间和备注；
- 下达前二次确认；
- 查看指令状态与执行结果；
- 对重复或冲突操作展示后端返回的明确原因。

### C-07 实现执行员工作台

- 查看分配给自己的指令；
- 查看目标、依据、优先级和截止时间；
- 接收或按规则拒绝；
- 标记开始执行；
- 填写结果、状态、说明和证据；
- 提交后查看完整记录。

### C-08 实现通用体验和可靠性

- 所有异步请求具有加载状态并防止重复点击；
- 成功、失败、权限不足和状态冲突有明确提示；
- 危险或不可逆操作需要二次确认；
- 长文本、空值、长用户名和多状态下布局不破坏；
- 表格分页、筛选和刷新行为一致；
- 基本键盘操作和表单标签可用。

### C-09 前端测试和联调

- 对关键组件和权限逻辑编写测试；
- 与 B 按 OpenAPI 联调，不私自发明字段；
- 对后端 400、401、403、404、409、422、500 等响应提供合理处理；
- 使用 A 提供的固定演示数据走通四角色流程；
- 提供关键页面截图和操作说明。

### C-10 编写用户手册

在 `docs/user-guide.md` 中按角色说明：登录、完成任务、查看状态、常见错误和退出。截图中的账号、IP 和数据应使用演示或脱敏内容。

## 页面验收原则

- 用户能看到当前角色和当前任务状态；
- 主操作明确，不能让用户猜下一步；
- 不展示其无权查看的数据；
- 刷新不会造成状态错乱；
- 后端拒绝操作时准确显示原因；
- 演示路径无需打开开发者工具或手改数据。

## 完成定义

C 的工作完成意味着：四类用户都能通过界面完成自己的操作，页面与后端权限和状态规则一致，异常状态可理解，完整流程可稳定演示，并有可供非开发人员使用的操作手册。
