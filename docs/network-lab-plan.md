# 四台电脑的组网与部署建议

> 本文是早期组网思路。**最终的三域拓扑、地址表、数据流矩阵与防火墙策略以
> [network-design.md](network-design.md) 为唯一权威来源**（数据库位置已按
> [ADR-002](adr/002-dmz-service-placement.md) 调整至 DMZ 服务侧，本文
> "数据库 10.0.1.20 放内网"的示例不再适用）。

## 结论

四台电脑不需要彼此用网线直接相连。

- 日常开发：四人各自在自己的电脑开发，通过 GitHub 同步代码，不要求处于同一局域网。
- 集成测试：四台电脑接入同一个受控局域网，能够同时访问目标系统即可。
- 中期验收和现场演练：推荐使用独立交换机或路由器进行有线连接，降低校园 Wi-Fi 隔离、地址变化和信号波动带来的风险。
- DMZ 与信任内网可以通过虚拟化软件中的不同虚拟网段实现，不要求为每个安全区域准备一组物理电脑。

## 推荐方案：一台基础设施主机 + 三台终端

由成员 D 的电脑作为基础设施主机，运行软路由和服务器虚拟机。A、B、C 的电脑主要作为不同角色的操作终端；D 的宿主机或另一台虚拟机作为第四终端。

```text
课程现场网络 / 外部测试网络
               |
          iKuai WAN
       [D 电脑中的软路由 VM]
          /            \
 LAN 10.0.1.1       DMZ 10.1.1.1
      |                    |
 独立交换机/AP      Web/API VM 10.1.1.20
      |                    |
 A/B/C/D终端        数据库 VM 10.1.1.30
 10.0.1.0/24       （仅允许 API 主机访问）
```

数据库位置必须与最终架构图保持一致。为严格满足验收中的“DMZ 主机无法访问内网主机服务”，当前基线将 Web/API 和数据库都放在 DMZ 服务侧的不同虚拟机或容器中。数据库不进行外网端口映射，仅允许 API 主机访问其数据库端口。如果实验条件有限，也可以把应用和数据库放在同一服务器，但仍须限制数据库监听地址和访问来源，并在报告中说明取舍。

## 推荐硬件

- 一台 5 口或 8 口千兆交换机；
- 至少四根网线；
- D 的电脑根据现有网卡情况准备一个 USB 转千兆网口；
- 有条件时准备独立小路由器或 AP，作为信任内网接入点；
- D 的电脑建议至少 16 GB 内存，以承载软路由、应用和数据库虚拟机。

设备不是必须全部购买。先盘点实验室是否提供交换机、路由器和现场局域网，再决定使用物理或虚拟方案。

## 为什么不建议四台电脑直接互连

- 普通笔记本通常只有一个网口，无法自然形成四节点网络；
- 点对点直连会增加静态路由和共享网络配置的复杂度；
- 使用交换机可让四台终端处于同一受控网段，地址和连通性更清晰；
- 拓扑中心仍应是软路由/防火墙，而不是某台成员电脑临时开启系统网络共享。

## 无交换机时的备选方案

### 方案一：独立 Wi-Fi 路由器

四台电脑连接同一个独立路由器的 Wi-Fi 或 LAN。D 的基础设施主机通过虚拟网卡创建 DMZ，并通过 iKuai 控制跨区访问。

注意：确认路由器没有启用 AP/客户端隔离，否则四台终端可能无法互访。

### 方案二：全部在 D 的电脑中虚拟化

在 D 的电脑中创建外部测试机、内网终端、DMZ 服务器和数据库虚拟机。其他成员通过屏幕演示或远程方式协作。

该方案能验证网络规则，但不充分体现“四台不同终端同时使用”。适合作为开发和备用环境，不建议作为条件允许时的唯一验收方案。

### 方案三：校园 Wi-Fi

只适合早期业务联调。校园 Wi-Fi 常有客户端隔离、动态地址和端口限制，现场演示风险较高，不作为首选验收网络。

### 方案四：手机热点作内网 + 虚拟三域（四台电脑、无交换机，推荐）

适用条件：四台电脑、一台手机、无交换机。**四条网络基础要求都能满足**，前提是 D 的电脑能把
Wi-Fi 网卡桥接给虚拟机（多数 VMware / VirtualBox 版本都支持，需先验证）。

#### 拓扑

```text
                 手机热点 192.168.43.0/24  ← 信任内网（同时是出网出口）
                    |
   ┌──────────┬─────┴─────┬──────────────┐
   A 终端     B 终端      C 终端          D 宿主机（浏览器=执行员终端）
                                          |
                             iKuai 的 LAN 口（桥接 Wi-Fi，192.168.43.10）
                                          |
              ┌───────────────────────────┴──────────────────────────┐
        VMware NAT 192.168.100.0/24                        Host-Only 10.1.1.0/24
        外部网络：iKuai WAN 192.168.100.2                  DMZ：iKuai 10.1.1.1
                  ext-test VM 192.168.100.10               Web/API 10.1.1.20:8080
                                                           MySQL 10.1.1.30:3306（不映射）
```

要点：

- **热点 = 信任内网**：四台终端默认网关是手机（本身就是外网出口，满足“内网可访问外网”）；
- **DMZ** 用 Host-Only 网段，天然与热点网段隔离；
- **外部网络** 用 VMware NAT 网段 + 一台轻量 VM（`ext-test`）模拟，从它访问 iKuai 的 WAN 口验证端口映射；
- iKuai 需要三块网卡：桥接 Wi-Fi（LAN）、Host-Only（DMZ）、NAT（WAN）；LAN 与 WAN 上各做一条
  80 → `10.1.1.20:8080` 的端口映射；
- 防火墙：LAN→DMZ 放行、DMZ→LAN 拒绝、DMZ→WAN 仅按需放行；DMZ→LAN 的拒绝要开日志。

#### 四条网络要求的验证命令

```bash
# 3) 三域划分：三个网段互不相同
ipconfig                     # 终端看到 192.168.43.x
ssh 10.1.1.20 'ip a'         # DMZ 看到 10.1.1.x
ssh 192.168.100.10 'ip a'    # 外部看到 192.168.100.x

# 4) 内网访问外网与 DMZ
ping -n 2 www.baidu.com                      # 经热点出网
curl -I http://192.168.43.10/                # 经 iKuai 映射到 DMZ 的 8080

# 5) 外网访问 DMZ（仅在 ext-test 上执行）
curl -I http://192.168.100.2/                # 200
nc -vz 192.168.100.2 3306                    # 失败：数据库未映射

# 6) DMZ 不能访问内网（在 10.1.1.20 上执行）
ping -c 2 192.168.43.10                      # 失败
curl -m 3 http://192.168.43.101/             # 失败
# 同时在 iKuai 上导出防火墙命中日志
```

#### 风险与退路

| 风险 | 先验证什么 | 退路 |
|---|---|---|
| 虚拟机**桥接 Wi-Fi 失败** | 先在 D 的电脑上起一台测试 VM，桥接后能否拿到 192.168.43.x | 换 USB 无线网卡专供桥接；或用 VirtualBox 的“桥接网卡”；仍不行则用方案二（全部虚拟化，报告注明终端为虚拟机） |
| 热点**客户端隔离** | 两台笔记本连热点互 ping | 换一台手机；或用 D 的 Windows 移动热点（需第二块无线网卡） |
| 热点**设备数上限**（常见 5–8） | 四台 + ext-test 一起连 | ext-test 放 VMware NAT 网段，不占热点名额 |
| 热点**网段变化** | 重启热点后 `ipconfig` 是否同段 | 现场重新记录地址，报告按实际填写 |
| 手机流量 | 演示数据只有几 MB | 提前把镜像/依赖都拉好，不在热点下装包 |

#### 四台电脑的角色分配

| 电脑 | 角色 | 同时承担 |
|---|---|---|
| D 的电脑 | 基础设施：iKuai + DMZ 两台 VM + ext-test VM | 现场演示时用浏览器登录**执行员**账号（第四终端） |
| A 的电脑 | 决策员终端 | 主持人/讲解 |
| B 的电脑 | 分析员终端 | 数据与接口讲解 |
| C 的电脑 | 侦察员终端 | 侦察与 AI 讲解 |

> D 的电脑同时跑 4 台 VM 吃紧时，可把 `ext-test` 换成手机上的浏览器访问 iKuai WAN 地址；
> 但必须在报告中说明“外部测试节点为手机”，且该手机需接入与 iKuai WAN 相同的网段——
> 实践中更省事的做法仍是保留一台轻量 Linux VM。

## 验收前测试

1. 四台终端能同时登录四类账号。
2. 内网终端能访问应用公开地址。
3. 外部测试机只能访问映射后的 Web/API 端口。
4. 外部测试机不能访问数据库和管理端口。
5. DMZ 主机不能访问任何内网主机服务；API 只访问同在 DMZ 服务侧的数据库。
6. 拔掉或禁用一条网络连接后，系统表现和恢复步骤有记录。
7. 防火墙允许/拒绝日志与测试结果一致。
8. 所有地址、账号、虚拟机和网线贴有清晰标签，现场能快速恢复连接。
