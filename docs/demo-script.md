# 固定演示数据与演示脚本

版本：1.0（已冻结，2026-10-27）

用途：统一中期验收的演示数据、账号、话术和时间分配，避免现场临时造数据导致结果不一致。
脚本实现在 [scripts/seed_demo_data.py](../scripts/seed_demo_data.py)，本文件是它的人读说明。

## 1. 演示目标与时长

| 项目 | 内容 |
|---|---|
| 目标 | 在真实接口与真实数据库上完整演示一次 OODA 协同链，并能从审计日志还原 |
| 总时长 | 8 至 12 分钟（讲解 3 分钟，操作 6 分钟，收尾 2 分钟） |
| 演示终端 | 四台终端分别登录四类角色，另有一台用于数据库与日志核对 |
| 演示角色 | A 决策员、B 分析员、C 侦察员、D 执行员 |

## 2. 演示环境前置条件

1. `docker compose up -d` 后，Gateway `/health/ready` 返回 `200`；
2. 各服务 `/health/ready` 均为 `ok`，MySQL 可连接；
3. 已执行数据库迁移，四类标准角色与权限种子存在；
4. 已执行 `python scripts/seed_demo_data.py --with-loop` 或至少完成一次闭环，
   保证列表页不是空的；
5. 四台终端时间同步，浏览器缓存已清理，演示账号可正常登录；
6. 三域网络已按 [组网方案](network-lab-plan.md) 配置，D 已准备连通与拒绝测试命令。

## 3. 演示账号与组织

组织结构（种子脚本创建）：

```text
联合指挥所  ORG-CMD
├── 侦察分队  ORG-REC   recon01 侦察员甲 / recon02 侦察员乙
├── 分析组    ORG-ANA   analyst01 分析员甲 / analyst02 分析员乙
├── 决策组    ORG-DEC   dmaker01 决策员甲
└── 执行分队  ORG-EXE   exec01 执行员甲 / exec02 执行员乙
```

| 账号 | 显示名 | 角色 | 用途 |
|---|---|---|---|
| `recon01` | 侦察员甲 | 侦察员 | 主演示提交侦察记录 |
| `recon02` | 侦察员乙 | 侦察员 | 演示同类多用户与候选筛选 |
| `analyst01` | 分析员甲 | 分析员 | 主演示分析报告 |
| `analyst02` | 分析员乙 | 分析员 | 演示多分析员结论并列 |
| `dmaker01` | 决策员甲 | 决策员 | 下达指令、查看结果 |
| `exec01` | 执行员甲 | 执行员 | 接收并执行 |
| `exec02` | 执行员乙 | 执行员 | 演示多执行员分配 |
| `admin` | 系统管理员 | 管理权限 | 仅用于配置与演示后台 |

密码规则：

- 管理账号口令由 `NIS_ADMIN_PASSWORD` 注入，演示账号口令由 `NIS_DEMO_PASSWORD` 注入；
- 两个值只放在本地 `.env`，不进入仓库、不写进报告、不投屏；
- 现场如需展示登录，输入框使用浏览器密码管理器或提前登录好的会话。

## 4. 固定演示内容

以下文本与种子脚本一致，演示时照读即可，避免临场编造。

### 4.1 侦察记录（recon01）

| 字段 | 值 |
|---|---|
| 标题 | 演示用：目标区域活动规律观察 |
| 来源类型 | `osint`（公开来源整理） |
| 来源说明 | 演示环境内部素材，已脱敏 |
| 可信度 | `medium` |
| 优先级 | `urgent` |
| 正文 | 在课程授权的演示环境中，观察到目标区域每日固定时段出现人员与车辆往返，路线相对固定，伴随无线电通联活动。以上内容为演示数据，不对应任何真实目标。 |

### 4.2 分析报告（analyst01）

| 字段 | 值 |
|---|---|
| 标题 | 演示用：区域活动规律分析 |
| 关联侦察 | 4.1 的记录 |
| 关键发现 | 活动时间与路线高度规律，具备固定保障节点特征。 |
| 关联关系 | 人员往返与车辆调度在同一时段出现，两者存在时间耦合。 |
| 风险等级 | `medium` |
| 建议手段 | 建议在固定时段前完成观察点部署，并保留影像证据。 |
| 优先级 | `urgent` |

### 4.3 决策指令（dmaker01）

| 字段 | 值 |
|---|---|
| 标题 | 演示用：固定时段观察任务 |
| 目标 | 在固定时段获取目标区域活动证据 |
| 正文 | 提前 30 分钟到达观察点，按约定频段通联，只做观察与记录，不主动接触。 |
| 优先级 | `urgent` |
| 接收执行员 | `exec01`（演示多执行员时追加 `exec02`） |
| 依据报告 | 4.2 的报告 |

### 4.4 执行结果（exec01）

| 字段 | 值 |
|---|---|
| 结论 | `success` |
| 摘要 | 按计划完成观察，取得 3 段连续记录。 |
| 详情 | 观察期间未发生异常接触，证据已按要求存放在受控目录。 |

## 5. 演示步骤与时间分配

| 时间 | 段落 | 操作人 | 动作 | 验收对应 |
|---|---|---|---|---|
| 0:00-0:40 | 开场 | A | 一页架构：四角色、Gateway、8 服务、三域网络 | — |
| 0:40-2:00 | 登录与 RBAC | C 操作，B 讲解 | 四类账号登录；用侦察员账号直接访问决策员页面与接口，出现 403 | 用例 8、9、10、11 |
| 2:00-3:20 | 侦察 + AI | C | 新建记录 → 请求 AI 摘要 → 修改后人工确认 → 选择分析员提交 | 用例 12、13、14 |
| 3:20-4:40 | 分析 | B | 读取被指派记录 → 编写报告引用证据 → 接受/修改 AI 建议 → 选择决策员提交；可展示 analyst02 的并列报告 | 用例 12、13、14 |
| 4:40-6:10 | 决策 | A | 并列对比报告 → 下达前冲突检查提示 → 二次确认 → 选择执行员下达 | 用例 12、14、15 |
| 6:10-7:40 | 执行 | D | 接收 → 开始 → 填写结果并提交；决策员页面刷新看到状态与结果 | 用例 12 |
| 7:40-9:00 | 审计还原 | A | 用一次提交的 `X-Request-ID` 查询调用链，还原四服务事件 | 用例 2 |
| 9:00-10:30 | 网络验证 | D | 内网访问 DMZ、外网访问映射端口、DMZ 访问内网被拒 | 用例 3、4、5、7 |
| 10:30-12:00 | 收尾 | A | 数据库核对一条记录、说明已知限制与扩展目标状态 | 用例 1 |

发言顺序：C（侦察员视角）→ B（数据与接口视角）→ A（决策与全局视角）→ D（网络与安全视角），
收尾由 A 总结。每人都要能解释自己那一段的技术选择与失败处理。

## 6. 故障时的备用路径

| 故障 | 现场处理 | 备用证据 |
|---|---|---|
| AI 服务不可用（503/504） | 明确说明“AI 可降级”，继续纯人工完成提交 | 提前录屏一次正常 AI 建议与人工确认 |
| 某个业务服务宕机 | 展示该工作台明确的失败提示，其他角色继续操作 | 服务健康检查截图、Compose 重启日志 |
| 数据库不可用 | 说明就绪检查失败与事务回滚，不制造半完成状态 | 迁移与恢复记录 |
| 网络三域环境不可用 | 切换到本地 Compose 拓扑，如实说明这是降级演示 | 提前保存的三域连通/拒绝测试截图与防火墙日志 |
| 演示数据被改乱 | 重新执行 `seed_demo_data.py --with-loop` 生成新记录 | 种子脚本输出中的对象 ID |
| 某账号无法登录 | 用备用同角色账号（`recon02`/`analyst02`/`exec02`）继续 | 账号清单 |

原则：宁可明确说“这一项现在不可用”，也不要现场改数据库或临时伪造页面数据。

- [ ] 演示数据已生成，列表页有四条以上记录
- [ ] 三域网络连通与拒绝测试各跑一次
- [ ] 审计日志能按 `request_id` 查到完整调用链
- [ ] 录屏/截图等备用证据已在本机就绪
- [ ] 报告、PPT、终端分辨率与投屏比例已调整
- [ ] 无真实密码、Token 显示在屏幕或浏览器地址栏
