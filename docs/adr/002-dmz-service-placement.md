# ADR-002：API 与中心数据库位于 DMZ 服务侧

状态：已接受（2026-10-27 随 baseline-1.0 冻结）
日期：2026-10-13

## 背景

基础验收要求外网能访问 DMZ 公开服务，同时要求 DMZ 主机无法访问内网任何主机服务。如果 API 位于 DMZ、数据库位于内网，API 到数据库连接会直接与拒绝测试发生冲突。

## 决策

Web/API 和中心数据库位于 DMZ 服务侧的不同虚拟机或容器。数据库不做外网端口映射，仅允许 API 主机访问数据库端口；DMZ 到信任内网全部拒绝。

## 后果

- 优点：可严格通过 DMZ 到内网拒绝测试，部署路径清晰。
- 代价：数据库位于安全暴露面更高的区域，需要主机隔离、访问白名单、低权限账号、备份和审计。
- 备选：若教师明确允许 DMZ 到内网数据库的单端口例外，再通过新 ADR 调整。

## 残留风险与确认事项

课程材料的常见表述是“中心数据库部署在内网”，与本 ADR 相反。当前三域拒绝测试的通过条件优先，
因此按本 ADR 执行；若任课教师现场明确要求数据库必须位于信任内网，需要：

1. 由 D 调整拓扑，把 MySQL 迁到内网并在 iKuai 上为 API 主机开单端口例外；
2. 由 A 建立变更 Issue 并新增 ADR 覆盖本条（不得只改文档不改拓扑）；
3. 同步更新 `docs/network-lab-plan.md` 的地址表与 `docs/test-report.md` 的拒绝测试结论。

该确认事项记入 Issue #26 的跟踪项，验收前由 A 向教师确认一次。
