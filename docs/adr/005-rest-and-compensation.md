# ADR-005：同步 REST 与补偿策略

状态：已接受

日期：2026-10-16

## 背景

OODA 流程包含多次跨服务调用。引入消息队列和分布式事务会显著增加课程项目的开发与验收风险。

## 决策

P0 阶段使用同步 REST/JSON。跨服务写操作采用本地事务、幂等键、有限重试、明确中间状态和人工/自动补偿，不使用两阶段提交。Workflow Coordinator 首期位于 Gateway 内部。

## 后果

- 调用链直观，易于使用 OpenAPI 测试和现场演示。
- 服务故障会产生同步失败，需要超时和清晰错误反馈。
- 跨服务业务只能达到最终一致，需要保留 `compensation_required` 等可恢复状态。
- 未来引入消息队列必须新增 ADR，且同步主流程继续可用。
